# 操作和按钮逻辑

## 导航

第一版保留四个入口：

```text
扫码 / 库存 / 新增 / 流水
```

## 扫码页定位

扫码页第一屏是 **一屏库存工作台**，聚焦：

```text
入库
更新库存
绑定库位
```

正常手机屏幕上，第一屏尽量不需要上下滑动。

页面结构：

```text
顶部: 入库 / 更新库存 / 绑定库位 三个模式按钮
中间: 摄像头扫码模块
底部: 当前模式步骤箭头，当前步骤高亮
```

低频内容不要常驻挤占扫码页：

```text
最近扫码
流水
完整 payload
调试信息
归档
撤销上一笔
清空上下文
```

这些放到更多按钮、底部弹层或独立页面。

## 三个模式

### 入库

步骤：

```text
物品码 -> 重量码/数量 -> 库位码 -> 入库确认
```

用途：

```text
新标签第一次进入库存
已出库物品重新入库
```

### 更新库存

步骤：

```text
物品码 -> 重量码/数量 -> 更新确认
```

用途：

```text
耗材重新称毛重
零件重新称总重并估算数量
```

### 绑定库位

步骤：

```text
物品码 -> 库位码 -> 绑定确认
```

用途：

```text
已有库存物品移动库位
```

## 扫码后的 App 内弹窗

弹窗是 App 内普通弹窗或底部弹层，不是系统悬浮窗，不需要额外权限。

### 物品码

扫到物品码后必须弹轻量确认窗。

耗材弹窗直接显示并允许编辑：

```text
ID
品牌
材料
颜色
tare_g 空盘/皮重，必填
备注，可选
```

零件弹窗直接显示并允许编辑：

```text
ID
名称
unit_weight_g 单件重量，必填
备注，可选
```

其他物品弹窗：

```text
ID
名称
备注，可选
```

规则：

- 二维码有值就预填。
- 核心计算参数缺失时必须补齐后才能确认。
- 确认后才进入下一步。
- 取消后不改变当前流程上下文。

### 重量码

扫到重量码后必须弹轻量确认窗。

显示：

```text
毛重 value_g
```

如果当前已确认耗材：

```text
空盘/皮重 tare_g
可用重量 = value_g - tare_g
```

如果当前已确认零件：

```text
单件重量 unit_weight_g
估算数量 = floor(value_g / unit_weight_g)
```

规则：

- 确认后才写入当前流程上下文。
- 耗材 `value_g <= tare_g` 时不能确认。
- 零件缺 `unit_weight_g` 时不能估算，应回到物品确认补单重。

### 库位码

扫到库位码后必须弹确认窗。

库位码只标识库位本身，不表示任何物品已经在这个库位。只有用户确认入库、绑定库位或进入整理模式后，App 才把库位 ID 写入数据库里的 item 当前状态。

如果扫到未知库位 ID，弹窗里要求填写或确认库位中文名称，并写入 `locations` 映射表。

入库模式：

```text
确认作为入库库位
取消
```

绑定库位模式：

```text
确认绑定到当前物品
取消
```

单独扫库位、没有当前物品时：

```text
整理该库位
作为入库库位
取消
```

## 写入确认

普通写库存操作必须明确确认：

```text
入库
更新重量/数量
绑定库位
出库
归档
```

这里的“必须确认”只表示会改本地数据，不等于都会进入 `transactions`。

库位整理模式是例外：进入整理模式后，连续扫已有库存物品可以自动写库位。

## 库存页

库存页负责搜索、筛选和查看，不作为第一版主要写库存入口。

控件：

```text
搜索
类型筛选
状态筛选
库位筛选
低库存筛选
```

默认只显示在库物品。

点击库存项进入详情，可查看固定字段、当前状态和流水摘要。详情页是否放出库、归档等动作，后续再确认。

## 新增页

新增页只生成和打印标签，不保存库存。

按钮：

| 按钮 | 作用 |
|---|---|
| 生成 ID | 按类型生成默认唯一 ID |
| 生成标签 | 生成 `v1;` 二维码内容 |
| 搜索/停止搜索打印机 | 搜索或停止搜索德佟蓝牙标签打印机 |
| 启动自动连接 | App 启动后自动连接上次打印机 |
| 打印 | 打印 40x30mm 标签 |
| 清空 | 清空当前表单 |

生成标签后，标签预览和完整 payload 可以放在 App 内弹窗或底部弹层，不要长期挤占页面。

没有：

```text
保存纯档案
保存并入库
```

## 流水页

流水页展示 `transactions`。

写操作包括：

```text
stock_in
checkout
stocktake
undo
```

不进入流水页：

```text
绑定库位
库位整理
归档
固定字段修改
```

这些动作直接更新 `items`。扫码输入事件和失败原因进入 `scan_logs`。
