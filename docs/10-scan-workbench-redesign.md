# 扫码台设计

## 结论

扫码页是第一版日常主入口。

设计目标：

```text
扫到什么 -> 展示当前上下文 -> 满足条件后显示明确按钮 -> 写本地 JSON
```

不要让用户先选择查库存、盘点或移库模式。普通流程由扫码内容和当前上下文决定。

## 页面结构

从上到下：

```text
内嵌相机预览
扫码控制按钮
当前上下文卡片
当前可执行动作
最近结果/流水
手动兜底入口
```

## 上下文模型

```text
pending_item
pending_weight
pending_qty
pending_location
active_location_sorting
last_undo
```

冲突保护：

```text
未完成入库时扫到第二个物品/重量/库位
  -> 默认不替换
  -> 用户确认后才替换
```

## 扫物品码

如果本地有 item：

```text
展示库存详情
允许出库、盘点、移库、归档
```

如果本地没有 item：

```text
展示标签固定信息
不写本地
等待重量/数量和库位后入库
```

如果同 ID 固定字段和本地记录冲突：

```text
提示冲突
用户选择保留本地或更新本地固定信息
```

## 扫重量码

```text
type=weight;value_g=...
```

如果当前是耗材，作为当前毛重。

如果当前是零件且有 `unit_weight_g`，可换算数量。

## 扫库位码

如果当前有待入库/已在库物品：

```text
设置 pending_location
等待按钮确认
```

如果单独扫库位码：

```text
提示整理该库位
```

## 整理库位模式

进入前确认一次。

进入后：

```text
每扫一个已在本地库存里的物品
  -> 自动写 location
  -> 写 move 流水
  -> 震动/声音提示
```

扫到未入库物品时不写本地，只提示先走入库。
