# 扫码台设计

## 结论

扫码页是第一版日常主入口。

设计目标：

```text
选择模式 -> 扫码 -> App 内弹窗确认 -> 满足条件后显示明确按钮 -> 写本地数据库
```

扫码页第一屏只保留高频入库和更新流程。低频信息下沉到更多按钮、底部弹层或独立页面。

## 页面结构

从上到下：

```text
入库 / 更新库存 / 绑定库位 三个模式按钮
内嵌相机预览和扫码控制
当前模式步骤箭头，当前步骤高亮
当前可执行动作
```

## 上下文模型

```text
pending_item
pending_weight
pending_qty
pending_location
active_location_sorting
last_undo
```

冲突保护：

```text
未完成入库时扫到第二个物品/重量/库位
  -> 默认不替换
  -> 用户确认后才替换
```

## 扫物品码

如果本地有 item：

```text
展示库存详情
按当前模式进入更新库存或绑定库位流程
```

如果本地没有 item：

```text
展示标签固定信息
不写本地
等待重量/数量和库位后入库
```

如果同 ID 固定字段和本地记录冲突：

```text
提示冲突
用户选择保留本地或更新本地固定信息
```

## 扫重量码

```text
type=weight;value_g=...
```

如果当前是耗材，作为当前毛重。

如果当前是零件且有 `unit_weight_g`，可换算数量。

## 扫库位码

如果当前有待入库/已在库物品：

```text
设置 pending_location
等待按钮确认
```

如果单独扫库位码：

```text
提示整理该库位
```

## 整理库位模式

进入前确认一次。

进入后：

```text
每扫一个已在本地库存里的物品
  -> 自动写 location
  -> 可写 scan_logs 作为整理成功记录
  -> 震动/声音提示
```

扫到未入库物品时不写本地，只提示先走入库。
