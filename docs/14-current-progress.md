## 当前默认产品原则

- 扫码是主输入，正常流程不提供手动 payload 输入。
- 写库存前尽量要求明确按钮确认。
- 库位整理模式是例外: 进入整理模式后，连续扫已有库存物品可以自动写库位。
- 未完成上下文里同类信息只保留一个；扫到第二个物品/重量/库位时默认不覆盖。
- 如果标签固定信息和本地记录冲突，必须提示用户选择，不自动覆盖。

## 0.4.1 已实现操作逻辑

扫码页第一屏改成一屏库存工作台：

```text
顶部: 入库 / 更新库存 / 绑定库位 三个模式按钮
中间: 摄像头扫码模块
底部: 当前模式步骤箭头，当前步骤高亮
```

第一屏聚焦入库和更新库存流程，最近扫码、流水、完整日志、调试信息、低频操作都下沉到更多按钮、底部弹层或独立页面。

扫码确认规则：

```text
物品码: 必须弹窗确认
重量码: 必须弹窗确认
库位码: 必须弹窗确认
```

物品码确认窗必须直接暴露核心计算参数：

```text
耗材 spool: tare_g 空盘/皮重，必填，可编辑
零件 part: unit_weight_g 单件重量，必填，可编辑
其他 other: name，备注可选
```

重量码确认窗显示毛重；如已有物品参数，顺手显示耗材可用重量或零件估算数量。

库位码确认窗按模式确认用途；单独扫库位时提供：

```text
整理该库位
作为入库库位
取消
```

数据层确认：

```text
items: 当前库存表
locations: location_id -> 中文名称的轻量映射表
transactions: 出入库和重量/数量更新主流水，不记录库位移动
scan_logs: 扫码输入事件日志，用于排查和回看
```

位置边界:

```text
物品二维码不存当前位置
库位二维码只标识库位本身
物品当前库位存在 items.location_id
库位中文名称存在 locations.name
```
