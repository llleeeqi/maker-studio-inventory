## 已验证

用户真机反馈:

- 扫码功能正常。
- tools 虚拟货架里的耗材、重量、库位扫码链路已可用。
- 连接德佟标签打印机功能正常。

当前可以继续沿用:

- `v1;` 二维码协议。
- 字段值 UTF-8 百分号编码，App 扫码后自动解码。
- 40x30mm 标签尺寸作为当前默认。
- 下一版直接起 SQLite/Room 数据库，表先定为 `items / transactions / scan_logs`。
- 新增页只生成/打印标签，不保存纯建档记录。
- 入库必须扫到物品、重量/数量、库位，并点击入库确认。

## 暂缓事项

- 标签打印的实际纸面效果还没有完成最终验收。

## 下一轮要定

下一轮重点不是框架选择，而是把手机 App 的操作逻辑定死:

- 每个页面保留哪些按钮。
- 每个按钮什么时候可点。
- 点击后立即写数据、进入确认态，还是只改变上下文。
- 扫码后自动触发哪些动作，哪些必须手动确认。
- 冲突、误扫、重复扫如何处理。
- 库存项详情页是否需要，以及详情页里有哪些动作。
- Room 数据库落地时的字段和迁移细节。

## 当前默认产品原则

- 扫码是主输入，正常流程不提供手动 payload 输入。
- 写库存前尽量要求明确按钮确认。
- 库位整理模式是例外: 进入整理模式后，连续扫已有库存物品可以自动写库位。
- 未完成上下文里同类信息只保留一个；扫到第二个物品/重量/库位时默认不覆盖。
- 如果标签固定信息和本地记录冲突，必须提示用户选择，不自动覆盖。

## 已确认的下一版操作逻辑

扫码页第一屏改成一屏库存工作台：

```text
顶部: 入库 / 更新库存 / 绑定库位 三个模式按钮
中间: 摄像头扫码模块
底部: 当前模式步骤箭头，当前步骤高亮
```

第一屏聚焦入库和更新库存流程，最近扫码、流水、完整日志、调试信息、低频操作都下沉到更多按钮、底部弹层或独立页面。

扫码确认规则：

```text
物品码: 必须弹窗确认
重量码: 必须弹窗确认
库位码: 必须弹窗确认
```

物品码确认窗必须直接暴露核心计算参数：

```text
耗材 spool: tare_g 空盘/皮重，必填，可编辑
零件 part: unit_weight_g 单件重量，必填，可编辑
其他 other: name，备注可选
```

重量码确认窗显示毛重；如已有物品参数，顺手显示耗材可用重量或零件估算数量。

库位码确认窗按模式确认用途；单独扫库位时提供：

```text
整理该库位
作为入库库位
取消
```

数据层确认：

```text
items: 当前库存表
transactions: 出入库/盘点/移库等库存事实流水
scan_logs: 扫码输入事件日志，用于排查和回看
```
